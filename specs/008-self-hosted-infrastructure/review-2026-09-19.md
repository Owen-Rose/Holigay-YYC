## Findings

1. **WireGuard has no hostname to dial.** `app.<domain>` and `staging.<domain>` are
   Cloudflare-proxied, so they resolve to Cloudflare, not the home IP. `host-setup.md` §6
   says `Endpoint = <your public IP or a DDNS name>`, but `ddclient_hosts` (T020
   `host_vars/pi.yml`) and the ddclient config in T015 §9 only update the two proxied
   names. **Fix**: add a DNS-only record such as `wg.<domain>` to T002 (create it), to the
   ddclient host list, and to the client config in §6.
2. **The desktop never learns the Pi's backup key when provisioned alone.** In
   `roles/restic/tasks/main.yml` the desktop's `authorized_key` task reads
   `hostvars['pi']['backup_key']`, which exists only when the Pi is in the same play run.
   T021 and T023 only ever run with `--limit desktop` / `--limit pi`, so `ssh desktop` from
   the Pi in T023 step 2 will be refused. **Fix**: T023 (or T021 step 7) runs
   `ansible-playbook site.yml --ask-vault-pass` across both hosts once.
3. **Staging checks out `main`; the upgrade runbook assumes `dev`.** `group_vars/all.yml`
   sets `holigay_branch: main` for both hosts, but `upgrade-stack.md` step 4 says "edit
   `compose.yml`, commit to `dev`. On the desktop: `git pull`". **Fix**:
   `host_vars/desktop.yml` sets `holigay_branch: dev`.
4. **`tasks.md` pre-writes every deliverable, untested.** 4,085 lines because it embeds the
   full Compose file, both Caddyfiles, every Ansible role, both backup scripts and all six
   runbooks. Reviewable now; but each file's first real run will find bugs. Example already
   visible: on the drill (`backup-restore.md` §3), `restore.sh` runs `docker compose up -d`
   with `set -euo pipefail`; the drill's `caddy` cannot bind :80 (staging owns it), so the
   script aborts before `docker compose ps` and the `rm -rf "$WORK"` cleanup. **Expect**
   edits during each task's validation step; once a task merges, the file in the tree is
   the truth — do not back-port into `tasks.md` beyond ticking.
5. **Constitution amendment is scheduled too late.** `.specify/memory/constitution.md` lists
   "Email: Resend for transactional delivery" under stack lock-in and `RESEND_API_KEY` in
   the environment contract. T008/T009 remove the SDK and the variable; the only amendment
   is in T026. **Fix**: fold a PATCH amendment into the T008/T009 PR (or record the lag as
   a time-boxed exception per Governance).
6. **T002 moves the domain's nameservers to Cloudflare.** That affects every record on the
   domain (MX, the carrd site, anything else), not only the app. Recreate them in the zone
   before switching. Note: since this review, `vendors.holigayeventsyyc.ca` went live on
   Vercel via GoDaddy (2026-09-20) — the DNS situation T002 assumes has moved; re-read T002
   and R7 against the current registrar/DNS setup before starting Phase 2.
7. **Workstation tooling.** `ansible-playbook` (T020 step 9) and `restic` (T022 step 7) are
   not installed; shellcheck and `caddy validate` run through Docker and are fine. Node
   here is 24; the image and CI pin 22 (harmless).
8. **T012 is a real change to the Vercel Production deploy** (env vars, `dev → main`
   promotion) gated on a verified Resend sending domain. The escape hatch under
   "Dependencies and execution order" covers a slow verification. (The domain has since
   been verified — 2026-09-20 — so T003 is largely done; record it in the evidence rows.)

Deliberately not nitpicked (they are right): single origin (R3), the pinning rule (R5),

## What `/speckit-implement` does here, and how to drive it

- The skill (`.claude/skills/speckit-implement/SKILL.md`) runs `check-prerequisites.sh`,
  gates on `checklists/requirements.md` (all ticked → passes), reads every spec doc, then
  executes phase by phase and **ticks tasks `[X]` as it completes them**, halting on a
  failure. It also has a step that creates/amends ignore files on its own initiative —
  check the `.gitignore` / `.dockerignore` diff on the first run.
- Mismatches with the constitution: it ticks on completion (constitution ticks on merge),
  it does not create branches, and it wants to run every phase in one go. **Drive it one
  task at a time**: create `008-Txxx` off `dev`, invoke with the task id as the argument,
  leave the tick until the PR merges. The `tasks.md` header already names
  `superpowers:subagent-driven-development` / `executing-plans` as the sub-skill; both give
  a review checkpoint per task.
- 13 of 27 tasks are `[manual]`; the agent stops at each and names the runbook section;
  the evidence row in `quickstart.md` is filled before ticking.

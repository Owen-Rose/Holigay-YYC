**Goal:** A vendor sees every application submitted with their account's address, whichever came first — the account, the application, or a signed-in submission — with the email locked to the account on the apply page and a plain explanation on the empty dashboard. The contact block stops asking for a phone number and asks instead "Where can we view your products?" with three links (the first required), shown the same way on the apply form, the profile form, the organizer review page and the CSV export. The fixed application form and its write path are gone. One migration, `015`, carries every schema and write-path change; it lands on each hosted project before the code that reads it.

**Architecture:** Migration `015` (research R1, R3–R5) adds `vendors.product_links text[]` with a shape CHECK, copies `website` into slot 1, adds the private `link_vendor_account_rows(uuid, uuid)` helper (both directions, one transaction, never re-points — FR-004), the `authenticated`-only no-argument `link_vendor_account()` self-heal RPC keyed on `auth.uid()` (FR-001, FR-003), and replaces `submit_public_application(jsonb)` in place (account address wins when signed in, writes `product_links`, ignores `legacy`/`attachments`/`phone`, ties inside the transaction — FR-002, FR-019). In the app: `resolveVendorId()` (R6) calls the self-heal from the five vendor loaders; the apply page passes the session address to the questionnaire form, which locks it, and the submit action overrides it again (R7); one `NoVendorProfile` RSC carries the FR-007 sentence (R8); one `product-links.ts` rule, one `ProductLinksFields` fragment and one `ProductLinksList` serve all four surfaces (R2, R9); `EXPORT_HEADERS` is written once (R11); the fixed form, its page branch, action, schemas and the `FileUpload` primitive are deleted (R10).

**Tech Stack:** TypeScript 5.9 strict; PL/pgSQL (migration `015`); Next.js 16.0.7 App Router (RSC page + client forms); React 19.2; `@supabase/ssr` ^0.8 (`auth.getUser()`); `@supabase/supabase-js` ^2.86 (`.rpc()`); `react-hook-form` ^7.68 + `zod` ^4.1 + `@hookform/resolvers`; `sonner`; Vitest 4 (`unit` jsdom + `security` node against the local stack); Supabase CLI (`db reset`, `gen types --local`). **No new packages.**

- Public submission stays **one** anon-callable transactional RPC with the same signature and return type (FR-022, research R3). Every tie is written by the helper, which never re-points a tied row or a tied profile (FR-004).
- `015` is append-only; no RLS policy, view, trigger or storage rule changes (FR-021). `src/types/database.ts` is regenerated, never hand-edited.
- **Rollout order** (spec Edge Cases, FR-025): `015` on the dev project (T004) **before** T005/T006 reach `dev`; `015` on prod (T014) **before** the BL-17 promotion (T015). The replacement RPC tolerates the old payload in between.
- The stored `phone` column, the fixed-form columns on `applications`, the `attachments` table and its policies, `uploadFile`, `AttachmentsList` and the questionnaire builder's `phone` question type all **stay** (FR-009, research R3/R10).

- Linking is role-agnostic (Clarifications 2026-10-31 Q3); Link 1 is required on both forms (Q2); the account address wins over a tampered one (Q1). Authorization for the self-heal follows the vendor-side model (`auth.getUser()` + RLS / `auth.uid()`-scoped RPC), classified in plan.md Complexity Tracking and written into Principle I by T017. From 2026-11-02: only the email is prefilled on the apply page — the business fields start empty even for a tied account and the submission updates the record (Q1, story 1 scenario 11, FR-006); case-insensitive matching belongs to the self-heal RPC only — the submission RPC keeps its exact lower-cased upsert (Q2, scenario 5); the organizers' feedback on the link shape never gates T014 (Q3, FR-025).
